# PHP 8.2.34 FPM 128M 4-worker pure-HTTP chain

Lab-only research note, curated from the main research log (`docs/110`).
Authorized lab targets only; see `ACCEPTABLE_USE.md` and `SECURITY.md`.
The engine chain is identical to the 1-worker 8.2.34 port
(`docs/research/fpm-8234-port.md`); this note covers only the multi-worker
orchestration (lab pinning) and the strict per-round assertions.

## Result

PHP 8.2.34 FPM (pre-fix for CVE-2026-109618/109619; real-CVE quadrant),
128M, `pm=static` 4 workers, scheduled with the lab `_sleep.php` page:

- in-run `ROUNDS=3` single invocation: **PASS=3/3** (248.3 s, ~83 s/round),
  every round `ASSERT4 OK`; measured sampler `gdb_hits=0`;
- `/srv/www/x.php` = 392 B, `GET /x.php?0=id` = `uid=33(www-data)`;
  R2a/R2a(K2) session bytes = 47 B / 70 B (same oracle as 1w);
- matrix `fpm-8234-http-4w` (`proof`, `oracle=http`, runner `fpm8511http`
  with `--profile 8234 --workers 4`): 3 independent **strict** runs PASS
  **103.4 / 168.2 / 138.7 s** (VM load; the judge is PASS + `ASSERT4`, not the
  duration; earlier loose runs were 83.7 / 84.2 / 83.8 s);
- code-audit re-runs: 3x PASS 85.1 / 83.5 / 83.5 s (old loose calibre);
- 1w regression on the same runner: **PASS=1/1** in 115.3 s (strict; 67.5 s
  early loose) - `WORKERS=4` is additive, `fpm-8234-http-1w` remains valid
  (75.6/75.6/75.5 s);
- lab matrix at registration: **59 = 50 proof + 2 refuse + 6 gap + 1 gate,
  22/59 `oracle=http`**; with the 8.5.11 4w added in the same release:
  **60 = 51 proof + 2 refuse + 6 gap + 1 gate, 23/60 `oracle=http`**.
  A/B stays **87.55 / 85.05**: pinning is a lab scheduling layer, not a new
  vulnerability primitive.

## Pinning method and ASSERT4

Per round (`WORKERS=4`): restart -> HTTP grow SP (7,048,390 B, 8/8 requests
200) -> restart -> 3x concurrent `GET /_sleep.php?t=$SLEEP_T&id=N` with 0.35 s
stagger -> wait for 3 distinct markers -> the only free child (4 - 3 = 1)
receives the prime `GET /_r41prime2.php?mb=114&pad=64` (500/0 B, OOM) and the
immediate R2a/R3 stage -> kill sleepers, next round.

- pin retries (<=3) when markers are not unique, free != 1 or children < 4;
  every reported round used `attempt=1`;
- `P4W_GDB=1` (optional calibration) asserts `primed_pid == free_pid` with the
  version-agnostic BG level parse; never used inside the 3/3 sampler runs;
- strict assertions (runner sha256 `2ebe2679...`): R2a / R2a(K2) = 502 and
  R3 = 200; `sleepers_alive` re-check during the stage; `level1_count==1`;
  `fatal=inferred(500/0B)` when `log_errors=Off`; wrapper requires
  `ASSERT4 OK` with no `FAIL`;
- child ids change per restart; judges use marker/free/primed identity and the
  SR/x.php oracles, never a fixed PID.

Strict `WORKERS=1` run on the same image: PASS=1/1, `prime_fatal=1`, 115.3 s
(early loose 67.5 s). Constants and assertions match
`docs/research/fpm-8234-port.md`; the 4w branch is a new path only.

## Limitations

- pinning is a lab scheduling precondition (`_sleep.php` + exclusive container
  + `pm=static` 4 + `cleanup=Off` ini + `request_terminate_timeout` >
  `SLEEP_T`); re-calibrate marker/free/SR after image/pool/page changes;
- `P4W_GDB=1` is calibration only; the 3/3 rounds are gdb-free;
- `log_errors=Off` means no fatal text: the OOM is judged from prime 500/0 B +
  SP truncation + calibrated `BG=1` + the SR oracle (`fatal=inferred`);
- 4w is not a new vulnerability primitive (same engine chain, lab scheduling)
  and timings are not a gate.
