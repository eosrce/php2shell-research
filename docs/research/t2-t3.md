# T2 and T3: open research notes

## T2 — chunked 128M / 8.4.26

T2 is the 8.4.26-specific `psv` phase difference. The facts:

```text
A-only  psv = chunk+0x73000   (10 runs, independent of a_extra)
real    psv = chunk+0x550a0   (post-rotate, 3/3)
delta       0x1d560           (caused by two rotate() calls)
```

The 8.4.26 `psv` sits below the allocation family (`0x69xxx+`), so the
carrier cannot reach it. The following were already excluded:

- pushing the carrier upward (needs 1019 fillers > `max_input_vars`);
- big-field blocks (their start is always `>=0x69xxx`);
- the header-line allocation channel (bin-256, step 0x100, start 0x60400;
  40 groups failed);
- 8.3/8.5 with the same config work directly, so this is an 8.4.26 special
  case.

**Next:** only compare the `psv` phase between 8.4.26 and 8.3/8.5. Do not
re-run the filler sweeps.

## T3 — de=Off / 8M

The A shape puts the OOM in `php_session_reset_id` (session stage), but the
read window is only 4000 bytes and all 47 leaked pointers are inside the chunk
— no libphp base.

The delta assumption (`libphp - chunk` constant) was measured and rejected:
spread `0xCA000`.

**Next:** find a second in-band leak channel that prints or discloses a libphp
pointer under 8M / `display_errors=Off`, or change the consumer. Do not
re-run the old delta/parameter sweeps.
